# DAG-S25 — Validator-set governance (Phase G)

**Status:** in flight
**Branch:** `consensus/dag-s25-validator-governance`
**Base:** `main` @ `e5680e4` (post-S24 merge)
**Paper ref:** Phase G — Authority Ring admission/exit, epoch boundaries, slashing-triggered ejection

## Goal

The validator set is currently frozen at genesis. Phase G makes it dynamic: authorities can be admitted (via stake-weighted election), can withdraw voluntarily, and are forcibly ejected on confirmed equivocation. Epoch boundaries are the atomicity point — governance actions queue during the epoch and apply transactionally at the boundary so the active set is consistent within any single epoch.

## Sub-workstreams (priority order)

1. **S25.1** Epoch tracking — `Epoch` type, `rounds_per_epoch` in `GenesisManifest`, `EpochState { current, last_boundary_round }` in daemon `State`. Detect boundary crossings during `try_commit`. Emit `epoch_boundary` event.
2. **S25.2** Governance Intent surface — add `Intent::AdmitAuthority { id, stake, mldsa_pubkey, bls_pubkey }`, `Intent::ExitAuthority { id }`, `Intent::EjectAuthority { id, proof_ref }`. Validate at execution time; queue actions until next boundary.
3. **S25.3** Registry mutation at epoch boundary — apply queued governance actions atomically. Update `AuthorityRegistry`, `ValidatorRegistry`, `StakeTable`, daemon `n_authorities`.
4. **S25.4** Slashing-triggered ejection — wire equivocation events (already detected at `gsx_consensus::equivocation` + `gsx_fastpath::equivocation`) to emit automatic `EjectAuthority` intents. 100% bonded stake forfeit per paper Invariant 5.
5. **S25.5** Integration test — 4-node, admit a 5th authority, advance past epoch boundary, assert active set updated. Byzantine variant: equivocator ejected within 1 epoch.

## Scope realism

This is a multi-session sprint. This session's goal: deliver S25.1 + S25.2 to production. S25.3–S25.5 in subsequent sessions.

## Out of scope

- Move-VM-driven governance contracts (genesis admission only for MVP).
- Cross-epoch state-root reset (handled by `gsx-execution::Checkpointer` already at every round).
- Stake-weighted authority elections (selection algorithm — MVP admits in-order; election logic is a future ADR).
- Authority withdrawal cooling-off period (immediate-effect MVP).
