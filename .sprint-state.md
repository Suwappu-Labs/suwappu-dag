# DAG-S22 — Fast-path lane wiring

**Status:** in flight
**Branch:** `consensus/dag-s22-fastpath-lane-wiring`
**Base:** `main` @ `1de5ef9` (post-S21 merge)
**IQ ref:** `docs/iq/IQ-003-fast-path-architecture.md` (Option 1 — parallel-lane, paper §6.4)

## Goal

Wire the existing `gsx-fastpath` crate (DAG-S8 + S9 closed at library scope) into the running `gsx-node` daemon so the fast-path lane is exercised at runtime, not just in proptests. Currently `WireMessage::FastPath(_)` is no-op in the daemon — paper Invariant §5 (100% slashing for fast-path equivocation) is untestable in production.

## Sub-workstream order

1. **S22.1** State + minimal proposer: extend `State` with `fastpath_pending` / `fastpath_committed` keyed by `(object, nonce)`; add `propose_fastpath(tx)` that creates a singleton-signer `FastPathCert` and broadcasts.
2. **S22.2** Fast-path receiver: on inbox `WireMessage::FastPath(cert)`, validate eligibility, union signer into local pending cert, sign + re-broadcast if not yet signed, finalize on quorum.
3. **S22.3** K-binding check: after quorum, schedule K-binding verifier against main-lane commits at `lineage_round + 4`; emit `fastpath_inconsistent` event on conflict.
4. **S22.4** Equivocation detection: on every FastPathCert receipt, check for conflicting `(object, nonce)` with different `payload_digest`; emit `fastpath_slashed` event with `FastPathEquivocationProof`.
5. **S22.5** Integration test: 4-node cluster, single-owner fast-path tx, assert quorum + commit + no slashing. Byzantine variant: 1 Authority signs two conflicting certs, assert slashing event within 1 epoch.

## Wire surface

No new `WireMessage` variants needed for MVP. Re-use `WireMessage::FastPath(FastPathCert)`:
- Proposer broadcasts `FastPathCert { tx, signers = {self_id} }` (singleton-signer "partial cert").
- Each receiver validates, unions their signer in, re-broadcasts.
- Quorum reached → `fastpath_committed` event emitted.

A new `WireMessage::FastPathTx(FastPathTx)` could be added later for cleaner separation but isn't required.

## Exit gate

## Out of scope

- Main-lane Move-object execution model (current execution layer only has `Intent::Transfer`)
- Validator-Ring vote on fast-path certs (Theorem 2 AND-gate is main-lane only per paper §6.2)
- Re-balancing of stake on slashed authorities (handled by validator registry, separate sprint)

## Open questions

- Should fast-path lane respect the synchronizer (S21.3) for orphan cert recovery? Probably yes — same pattern. Address in S22.6 if needed.
- Per-tx wire-message volume: each tx generates up to N broadcast cycles. For high TPS this becomes a fanout pressure. Defer optimization to S22.7.
