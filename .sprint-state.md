# DAG-S23 — LTP attestation lane wiring

**Status:** in flight
**Branch:** `consensus/dag-s23-ltp-lane-wiring`
**Base:** `main` @ `2dc7ec8` (post-S22 merge)
**Paper ref:** §10 (Lattice Transfer Protocol), companion paper `gsx-papers/papers/ltp`

## Goal

Wire the existing `gsx-ltp` crate (DAG-S15 + S16 + S17 closed at library scope) into the running daemon. Currently `WireMessage::Ltp(CorridorAttestation)` is no-op; paper §10's 7-of-9 BLS attestation pipeline is exercised only in proptests. After this PR, the LTP lane is *live and listening* — corridor attestations from super-nodes are received, verified (when corridor config is loaded), and tracked per corridor id.

## Sub-workstreams

1. **S23.1** State + receiver: `State::ltp_latest: HashMap<CorridorId, AttestationPayload>` + inbox handler that accepts `WireMessage::Ltp(CorridorAttestation)`, logs `ltp_attested`, and stores latest payload per corridor.
2. **S23.2** Verification path: when a corridor definition (`Corridor` with 9 BLS pubkeys) is available at runtime, run `gsx_ltp::verify_attestation` before accepting. Genesis-manifest corridor config follows in a separate sprint; MVP accepts unverified.
3. **S23.3** DA SLA monitor: skeleton hook for `verify_sla` from `gsx-ltp::da`. Latency tracking deferred until LTP commitment-node integration ships.
4. **S23.4** Smoke test: assert state evolves correctly on a mock attestation.

## Event log

| Event | Lane | Trigger |
|---|---|---|
| `ltp_attested` | ltp | Inbox received a CorridorAttestation |
| `ltp_verified` | ltp | (S23.2) verify_attestation passed |
| `ltp_invalid` | ltp | (S23.2) verify_attestation failed |
| `ltp_sla_breach` | ltp | (S23.3) DA SLA exceeded |

## Exit gate

`cargo test -p gsx-node --lib ltp_receiver_records_attestation` plus existing `gsx-ltp/tests/proptest_attestation.rs`, `proptest_da.rs`, `proptest_did_stark.rs` stay green.

## Out of scope

- Corridor genesis-manifest config (real BLS public keys for 9 super-nodes per corridor) — separate sprint
- LTP commitment-node deployment + payload-availability backend — separate ops sprint
- DID rotation STARK proof verification on the live cluster — DAG-S17 ships the math; runtime wiring needs proof-submission UX
