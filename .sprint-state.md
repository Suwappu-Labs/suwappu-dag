## Note on proptest strategy

First 10k run hit `Too many global rejects` because `prop_assume!(amount
<= cap)` rejected ~50% of randomly-paired (cap, amount) tuples. Fixed
via `prop_flat_map` strategy composition that derives `amount` from
`cap`. The constraint is now structural, not assumed.

## Properties verified

1. **`issuer_mint_burn_atomic`** (EXIT GATE) — mint(n) followed by a
   completed two-phase burn(n) restores outstanding and circulating
   supply to pre-mint state. The total_minted and total_burned
   counters each increase by `n`; their difference is preserved.
2. **`mint_respects_delegation_cap`** — minting that would push the
   issuer's outstanding supply above `delegation_cap` fails with
   `DelegationCapExceeded`.
3. **`duplicate_finalize_burn_rejected`** — the duplicate-redemption
   attack vector: once a `BurnId` is finalized, a second `finalize_burn`
   on the same id returns `UnknownBurn`. Paper §8.2 "closes the
   duplicate-redemption attack vector."
4. **`expired_burn_can_be_reversed`** — `reverse_burn` succeeds
   strictly after the SLA deadline; at-or-before returns
   `SlaNotExpired`.
